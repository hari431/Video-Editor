LOCKS AND DEADLOCKS
===================

Locks coordinate concurrent access to shared database resources. Deadlocks occur when transactions wait on each other in a cycle.

DEADLOCK EXAMPLE
----------------
Transaction A locks row 1 then waits for row 2, while transaction B locks row 2 then waits for row 1. Neither can proceed.

PREVENTION
----------
Consistent lock ordering, short transactions, appropriate indexes, and avoiding unnecessary locking can reduce risk.

HANDLING
--------
Databases can detect deadlocks and abort one participant. Applications should be prepared to retry operations when the database contract recommends it.

COMMON MISTAKES
---------------
Assuming deadlocks mean the database is broken, holding locks while doing external work, and acquiring resources in inconsistent order.

KEY TAKEAWAYS
-------------
Deadlocks are often a coordination problem. Design transaction order consistently and handle retryable failures appropriately.
