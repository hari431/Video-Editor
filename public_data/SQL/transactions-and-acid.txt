TRANSACTIONS AND ACID
=====================

A transaction groups related database operations into a unit with defined consistency behavior. ACID describes important transactional properties.

ACID
----
Atomicity means all-or-nothing behavior. Consistency means transactions preserve declared/application integrity rules. Isolation controls interaction between concurrent transactions. Durability means committed data survives according to the database's guarantees.

EXAMPLE
-------
Moving money between accounts should not leave only the debit committed if the credit fails.

PRACTICAL DESIGN
----------------
Keep transactions focused. Long transactions can hold locks and resources longer than necessary.

COMMON MISTAKES
---------------
Performing slow network calls inside a database transaction, forgetting rollback behavior, and assuming ACID eliminates all application-level consistency problems.

KEY TAKEAWAYS
-------------
Transactions provide controlled atomicity and isolation, but transaction boundaries must be designed carefully.
