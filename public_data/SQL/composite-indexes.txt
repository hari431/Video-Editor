COMPOSITE INDEXES
=================

A composite index contains multiple columns in a defined order. Column order matters because it affects which predicates and ordering requirements can benefit.

LEADING COLUMNS
---------------
A composite index on (customer_id, status) is naturally useful for access patterns beginning with customer_id. The exact capabilities depend on the database optimizer.

EXAMPLE
-------
For queries commonly filtering by customer_id and then status, an index aligned to that access pattern may be useful.

ORDERING
--------
Column order can also support certain ORDER BY patterns. The best definition depends on equality predicates, range predicates, sorting, and selectivity.

COMMON MISTAKES
---------------
Assuming column order never matters, creating many overlapping indexes, and designing indexes without examining production query patterns.

KEY TAKEAWAYS
-------------
Composite indexes are about access patterns and column order. Measure against actual workload.
