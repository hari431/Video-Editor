CONSTRAINTS
===========

Constraints allow the database to enforce data integrity rules such as uniqueness, required values and relationships.

COMMON CONSTRAINTS
------------------
Primary keys identify rows. Foreign keys protect relationships. UNIQUE constraints prevent duplicate values according to database semantics. NOT NULL requires a value. CHECK can enforce predicates where supported.

WHY DATABASE ENFORCEMENT MATTERS
--------------------------------
Application validation is useful, but concurrent transactions can bypass assumptions made only in application code. Database constraints provide a final integrity boundary.

EXAMPLE
-------
CREATE TABLE policy (
    id BIGINT PRIMARY KEY,
    customer_id BIGINT NOT NULL,
    policy_number VARCHAR(50) UNIQUE
);

COMMON MISTAKES
---------------
Relying entirely on application validation, creating foreign keys without understanding delete/update behavior, and adding constraints without planning existing dirty data.

KEY TAKEAWAYS
-------------
Use database constraints as part of the data model, not merely as an optional safety net.
