SUBQUERIES
==========

A subquery is a query nested inside another SQL statement. It can express existence checks, scalar calculations, or derived result sets.

CORRELATED VS NON-CORRELATED
----------------------------
A non-correlated subquery can be evaluated independently. A correlated subquery refers to columns from the outer query and conceptually runs in relation to each outer row, although optimizers may transform it.

EXAMPLE
-------
SELECT p.id
FROM policies p
WHERE EXISTS (
    SELECT 1
    FROM claims c
    WHERE c.policy_id = p.id
);

EXISTS
------
EXISTS is often a natural way to ask whether related rows exist without needing columns from those rows.

COMMON MISTAKES
---------------
Using nested queries when a clear join is simpler, misunderstanding duplicate behavior, and assuming correlated syntax necessarily means poor performance.

KEY TAKEAWAYS
-------------
Use subqueries when they express the business question clearly; EXISTS is especially useful for existence checks.
