INDEXES
=======

Indexes are data structures that can help a database locate rows without scanning an entire table, but they also add storage and write overhead.

BASIC IDEA
----------
An index is useful when its ordering and selectivity help the optimizer find or order the needed data efficiently.

B-TREE VS HASH CHOICE
---------------------
Most OLTP indexes are B-Tree (ordered); hash indexes help only equality. For range or ORDER BY, B-Tree is required.

CREATE TABLE policies(policy_number text, status text, effective_date date);
CREATE INDEX ON policies(policy_number); -- B-Tree default in Postgres
-- Composite ordered index for common filter + sort:
CREATE INDEX ON policies(status, effective_date DESC);

EXAMPLE AND PLAN
----------------
If queries frequently search policies by policy_number, an appropriate index may make that lookup efficient. The exact index definition depends on the database and access patterns.

EXPLAIN SELECT * FROM policies WHERE policy_number = 'P123';
-- Index Scan using policies_policy_number_idx on policies (cost=0.42..8.44 rows=1)

For `WHERE status='ACTIVE' ORDER BY effective_date DESC` the composite index above allows an index scan in order; a single-column `status` index would still require a separate sort.

TRADE-OFFS WITH MEASUREMENT
---------------------------
Every index consumes space and must generally be maintained as data changes. Too many indexes can slow writes and complicate optimization. Measure write overhead via `pg_stat_user_indexes` and `EXPLAIN (ANALYZE, BUFFERS)` before adding a third index on the same table.

COMMON MISTAKES
---------------
Indexing every column, ignoring query shape, assuming indexes are always used, and creating indexes without checking execution plans. Also creating `(effective_date, status)` when queries filter by `status` alone — the leading column must match the predicate for efficient use.

KEY TAKEAWAYS
-------------
Index design should begin with real query patterns and workload, not with a rule that every searchable column needs an index.
