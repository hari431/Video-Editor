EXECUTION PLANS
===============

An execution plan describes how the database intends to retrieve and process data. It is one of the most useful tools for diagnosing query performance.

WHAT TO INSPECT
---------------
Look for scans, index access, join methods, estimated vs actual row counts where available, sorts, aggregation cost, and expensive operators.

CARDINALITY
-----------
Bad row-count estimates can lead the optimizer to choose a poor plan. Statistics and data distribution influence these estimates.

PRACTICAL WORKFLOW
------------------
Capture the query, inspect the plan, identify the expensive or surprising operator, make a targeted change, then compare measurements.

COMMON MISTAKES
---------------
Reading only one plan, ignoring actual runtime, and assuming a named index in a plan automatically means the query is optimized.

KEY TAKEAWAYS
-------------
Execution plans turn performance discussions from guesses into evidence.
