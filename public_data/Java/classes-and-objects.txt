CLASSES AND OBJECTS
===================

Classes define structure and behavior; objects are runtime instances of classes. This is the foundation for object-oriented Java design.

CLASS STRUCTURE
---------------
A class can contain fields, constructors, methods, nested types, and initialization logic. Public APIs should expose only what callers need.

OBJECT LIFECYCLE
----------------
Objects are created with new or by factories and become eligible for garbage collection when no longer reachable. Constructors establish valid initial state.

EXAMPLE
-------
class Account {
    private final String id;
    Account(String id) { this.id = id; }
    String getId() { return id; }
}

ENCAPSULATION
-------------
Private fields combined with controlled methods help protect invariants. Prefer behavior-oriented methods over exposing mutable state unnecessarily.

COMMON MISTAKES
---------------
Creating classes that only hold data without clear responsibility, exposing mutable collections directly, and putting unrelated responsibilities into one class lead to fragile designs.

KEY TAKEAWAYS
-------------
Good classes protect their invariants, have focused responsibilities, and expose a small, intentional API.
