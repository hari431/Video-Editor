SOLID PRINCIPLES
================

SOLID is a set of design principles that can improve maintainability when applied as reasoning tools rather than rigid rules.

THE PRINCIPLES
--------------
Single Responsibility concerns focused reasons to change. Open/Closed encourages extension without repeatedly modifying stable code. Liskov Substitution concerns behavioral substitutability. Interface Segregation discourages forcing clients to depend on irrelevant methods. Dependency Inversion encourages high-level policy to depend on abstractions.

PRACTICAL EXAMPLE
-----------------
A policy rating service can depend on a RatingStrategy interface rather than constructing one concrete algorithm internally. Different strategies can then be substituted and tested.

AVOID DOGMA
-----------
SOLID can be over-applied. Creating dozens of interfaces and classes for tiny programs can make code harder to understand.

COMMON MISTAKES
---------------
Treating SOLID as a checklist, confusing small classes with good design, and creating abstractions before the actual variation is understood.

KEY TAKEAWAYS
-------------
SOLID is a set of design heuristics. Apply the principles when they reduce coupling or clarify change boundaries.
