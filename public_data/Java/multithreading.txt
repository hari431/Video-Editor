MULTITHREADING
==============

Multithreading allows multiple tasks to make progress concurrently. It can improve throughput or responsiveness, but introduces coordination and correctness concerns.

CONCURRENCY VS PARALLELISM
--------------------------
Concurrency is about managing multiple activities; parallelism is about executing work simultaneously. A concurrent program is not automatically faster.

SHARED STATE
------------
The hardest problems often come from shared mutable state. Immutability, confinement, message passing, and well-defined synchronization can reduce risk.

EXAMPLE
-------
ExecutorService executor = Executors.newFixedThreadPool(4);
executor.submit(() -> processBatch());

COMMON MISTAKES
---------------
Creating unbounded threads, modifying shared state without synchronization, assuming execution order, and ignoring shutdown/error handling.

KEY TAKEAWAYS
-------------
Concurrency should be designed around ownership, coordination, and lifecycle—not simply adding threads.
