JVM MEMORY AND GARBAGE COLLECTION
=================================

The JVM manages memory for Java applications, including object allocation and garbage collection. Understanding the model helps diagnose performance and memory problems.

HEAP AND STACK
--------------
Objects are generally allocated on the heap, while each thread has stack frames for method execution. Exact implementation details can vary, so avoid treating simplified diagrams as the whole JVM.

GARBAGE COLLECTION
------------------
The garbage collector identifies objects that are no longer reachable and reclaims memory. Collection behavior depends on the selected JVM and collector.

PRACTICAL DEBUGGING
-------------------
Look for allocation rate, retained objects, heap occupancy, GC pauses, and application behavior rather than assuming every memory issue is a leak.

COMMON MISTAKES
---------------
Calling System.gc() as a routine fix, confusing high memory usage with a leak, and retaining references in caches or static structures unintentionally.

KEY TAKEAWAYS
-------------
Think in terms of object reachability, allocation, retention and runtime behavior rather than simplistic 'heap equals memory' explanations.
