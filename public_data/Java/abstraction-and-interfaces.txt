ABSTRACTION AND INTERFACES
==========================

Abstraction focuses on what a component promises rather than how it performs the work. Interfaces are a major Java mechanism for expressing contracts.

INTERFACE CONTRACT
------------------
An interface can define operations that implementations provide. Modern Java also supports default and static interface methods, but interfaces should still represent meaningful contracts.

EXAMPLE
-------
interface PaymentGateway {
    PaymentResult charge(Money amount);
}

BENEFITS
--------
Consumers can depend on PaymentGateway rather than a specific provider. This improves substitution, testing, and separation of concerns.

ABSTRACT CLASSES
----------------
An abstract class can combine shared state or behavior with abstract methods. It is useful when implementations genuinely share a base identity or invariant.

COMMON MISTAKES
---------------
Creating interfaces for every class without a meaningful abstraction and putting implementation details into a supposedly generic contract.

KEY TAKEAWAYS
-------------
Use abstraction to define stable contracts. Choose interfaces for capability/contract-oriented design and abstract classes when shared base behavior is genuinely useful.
