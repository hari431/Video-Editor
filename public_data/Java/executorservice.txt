EXECUTORSERVICE
===============

ExecutorService separates task submission from thread management. It is generally preferable to creating raw threads for application workloads.

WHY EXECUTORS
-------------
An executor can control concurrency through a pool and provide lifecycle operations such as shutdown.

EXAMPLE
-------
ExecutorService pool = Executors.newFixedThreadPool(4);
try {
    Future<?> future = pool.submit(this::work);
    future.get();
} finally {
    pool.shutdown();
}

SIZING
------
Pool size should reflect workload characteristics, resource limits, and the cost of tasks. A CPU-heavy task and an I/O-heavy task have different characteristics.

COMMON MISTAKES
---------------
Never shutting down an executor, using a pool size without measurement, and submitting tasks that wait indefinitely for work from the same constrained pool.

KEY TAKEAWAYS
-------------
Executors provide controlled concurrency and lifecycle management. Pool configuration should follow workload characteristics rather than arbitrary numbers.
