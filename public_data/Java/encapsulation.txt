ENCAPSULATION
=============

Encapsulation protects an object's state and exposes controlled operations. It is more than simply declaring fields private.

INVARIANT PROTECTION
--------------------
A well-encapsulated object prevents invalid combinations of state. Validation belongs close to the rule it protects.

EXAMPLE
-------
class Policy {
    private int deductible;
    void changeDeductible(int value) {
        if (value < 0) throw new IllegalArgumentException();
        deductible = value;
    }
}

COLLECTIONS
-----------
Returning internal mutable collections directly can break encapsulation. Depending on the API, return an immutable view or defensive copy when appropriate.

COMMON MISTAKES
---------------
Generating unrestricted getters/setters for every field can expose implementation details and make domain rules difficult to enforce.

KEY TAKEAWAYS
-------------
Encapsulation is about protecting invariants and controlling how state changes, not merely hiding fields.
