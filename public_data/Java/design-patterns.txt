DESIGN PATTERNS
===============

Design patterns are recurring design approaches for common problems. They are vocabulary and guidance, not mandatory templates.

COMMON PATTERNS
---------------
Factory patterns separate object creation decisions. Strategy encapsulates interchangeable algorithms. Observer represents event-style notification. Adapter translates one interface to another. Builder can make complex object construction clearer.

EXAMPLE
-------
A rating engine could expose a Strategy abstraction so different rating approaches can be selected without changing the caller.

CHOOSING PATTERNS
-----------------
Start with the problem and forces: changing algorithms, complex construction, integration boundaries, or event notification. Then select a pattern only if it simplifies the design.

COMMON MISTAKES
---------------
Adding patterns because they sound sophisticated, creating unnecessary indirection, and copying textbook structures without understanding the trade-off.

KEY TAKEAWAYS
-------------
Patterns should solve real design problems. The simplest understandable design is preferable to pattern-heavy code.
