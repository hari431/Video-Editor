POLICYCENTER PREEMPTION
=======================

Preemption concerns competing transactions initiated from the same underlying policy period where one transaction's processing can affect another.

CONCEPT
-------
If two users or processes begin transactions from the same base policy state, the system must prevent inconsistent concurrent changes.

REFERENCE GROUNDING
-------------------
The supplied PolicyCenter reference describes preemption as transactions initiated from the same base period.

PRACTICAL SCENARIO
------------------
A policy change and another transaction may both start from the same version. If one binds first, the other may require special handling.

COMMON MISTAKES
---------------
Confusing preemption with out-of-sequence processing. OOS is primarily about effective-date order; preemption is about competing transaction bases/concurrency.

KEY TAKEAWAYS
-------------
Preemption is a concurrency/history concept: competing transactions may be based on the same policy state.
