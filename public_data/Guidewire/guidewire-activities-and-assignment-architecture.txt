GUIDEWIRE ACTIVITIES AND ASSIGNMENT ARCHITECTURE
================================================

Activities and assignment connect automated insurance processing with human work.

ACTIVITY
--------
An activity represents work that needs completion, such as review, investigation or follow-up.

ASSIGNMENT
----------
Assignment determines the user or group responsible for that work. Rules may use organization, workload, geography, role or other criteria.

ACTIVITY PATTERN AND LIFECYCLE
------------------------------
An Activity is instantiated from an ActivityPattern (configured in Studio). Key fields: `Subject`, `Priority`, `AssignmentStatus`, `EscalationDate`, `TargetDate`. Lifecycle: Open → Assigned → Completed (or Skipped/Expired). An Activity may be tied to a related entity (`PolicyPeriod`, `Claim`, `UWIssue`) so the work is traceable.

GOSU CREATION EXAMPLE
---------------------
Creating an Activity from a PolicyPeriod inside a bundle:

var pattern = ActivityPattern.finder.findActivityPatternByCode("uw_approval")
Transaction.runWithNewBundle(\bundle -> {
  var activity = bundle.add(period).createActivity(pattern)
  activity.AssignedGroup = Group.finder.findGroupByName("UW Team")
  activity.AssignedUser = null // leave unassigned for group queue
  activity.TargetDate = Date.Today.addDays(3)
})

Group-queue assignment leaves `AssignedUser` null so any group member can claim it; setting a specific user bypasses the queue and may violate workload balancing.

PRACTICAL EXAMPLE WITH UWISSUE
------------------------------
An underwriting issue can generate an activity and route it to a group. Authority rules can then determine who may resolve or approve the issue. The UWIssue holds `ApprovalBlockingPoint` which blocks `Job#quote` or `Job#bind` until the owning activity is completed by a user whose `AuthorityProfile` includes that `UWIssueType`.

COMMON MISTAKES
---------------
Confusing activity assignment with approval authority. Also completing the Activity via UI without clearing the underlying `UWIssue`, which still blocks bind, or assigning directly to a user without considering `Group` membership and calendar.

KEY TAKEAWAYS
-------------
Activities represent work; assignment routes work; authority governs what the recipient may do.
